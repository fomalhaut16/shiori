# shiori（栞）

読書の進み具合を Slack で記録し、止まっている本や積読を知らせる個人用の bot です。
スマホの Slack から `128` と送るだけで、今読んでいる本のページが記録されます。

## Slack での使い方

bot との DM に送ります。

| やりたいこと | 送る内容 |
| --- | --- |
| 今のページを記録する | `128`（`128p`、`１２８`、`p.128` でもよい） |
| 進んだページ数で記録する | `+20` |
| 本を指定して記録する | `#3 128` または `メロス 128`（書名の一部） |
| 飛ばし読みを記録する | `120-144 160-188`（`120〜144、160〜188` でもよい。本の指定は `#3 120-144`） |
| 積読に追加する | `追加 9784101006017`（ISBN から書名とページ数を取得）、`追加 書名 320` |
| まとめて追加する | 1 行目に `追加`、2 行目から 1 行 1 冊 |
| 読み始める・中断・読了 | `開始 #3`、`中断`、`読了` |
| 総ページ数を直す | `総ページ #3 350` |
| 本を削除する | `削除 #3`（本の指定は必須。取り消せる） |
| 一覧を見る | `一覧`、または空のメッセージ |
| 直前の記録を取り消す | `取消`（返信に付く「取り消す」ボタンでもよい） |
| 使い方を見る | `?` |

本の指定を省くと、読書中の本が 1 冊ならその本に記録します。
2 冊以上あるときは、どの本か選ぶボタンが返ってきます。

本ごとに「読んだ範囲」と「栞（最後に読んだページ）」を持っています。
`128` や `+20` は、栞からそのページまでを読んだ範囲に足します。
`120-144 160-188` は書いた範囲をそのまま足し、栞は最後に書いた範囲の終わり（188）に移ります。
進み具合は、重なりを除いた読んだページの合計で数えます。読み返した所を二重には数えません。

全ページを読むと読了になります。飛ばした所を残したまま終えるときは `読了` と送ります。
積読や中断中の本にページを記録すると、読書中に切り替わります。

ホームタブ（bot の名前を押すと開く画面）には、直近 7 日の読書量のグラフ、読書中の本、中断中の本、積読が出ます。

- 進捗バーは、ページのどこを読んだかを表す地図です。一覧では 19 マス、記録したときの返信では 19 マス × 3 段で出します。飛ばした所は空いたまま残り、未読の範囲も文字で出ます。
- 「ページを記録」を押すと、テンキーで打てる欄が 2 つ出ます。「どこまで」だけなら栞の続きから、「どこから」も書けばその範囲を記録します。
- 各本の「︙」から、中断・再開・読了・総ページの修正・削除ができます。削除は確認画面を挟みます。

削除した本は一覧から消えますが、読んだ記録は残り、取り消しもできます。同じ ISBN をもう一度追加すると積読に戻ります。

## 届く通知

| いつ | 何が届くか |
| --- | --- |
| 毎週日曜 21 時 | 1 週間に読んだページ数、読み終えた本、読書中の本の進み具合と読了見込み、積読の数 |
| 毎日 21 時 | ページが 3 日進んでいない本があれば、その本。読書中の本がなければ、古い積読から 3 冊 |

何もなければ毎日の通知は届きません。同じ本への催促は 3 日に 1 回までです。
時刻と日数は `.env` で変えられます。

## 仕組み

```text
スマホの Slack ──▶ Slack ◀──── 常時接続（Socket Mode）──── このPC: ruby bin/shiori
                                                              ├─ data/shiori.db（SQLite）
                                                              ├─ data/backups/（毎日）
                                                              └─ data/shiori.log
```

PC から Slack へ接続しにいくので、公開 URL もサーバーも要りません。費用はかかりません。

PC が止まっている間に送った DM は、Slack からは届きません。
そこで起動するたびに DM の履歴を読み、まだ処理していないものを古い順に処理します。
送れなかった定期通知も、起動後に 1 回だけ送ります。

記録はすべて履歴（`events` テーブル）に残ります。ペースや週のページ数はここから計算します。
取り消しも履歴をもとに、変更前の状態へ戻します。

## セットアップ

### 用意するもの

| もの | どこで手に入るか |
| --- | --- |
| Slack のワークスペースでアプリを追加できる権限 | 自分のワークスペースなら持っています。研究室のワークスペースでは管理者の承認が要ることがあります |
| 自分の Slack メンバー ID（`U` で始まる） | Slack で自分のプロフィールを開く →「︙」→「メンバー ID をコピー」 |
| 通知を送るチャンネルの ID（`C` で始まる。DM でよければ不要） | チャンネル名を押す → 詳細画面のいちばん下 |
| Ruby 3.3 以上 | このPCには 3.4 が `C:\Ruby34-x64` に入っています |

### 手順

1. **Slack アプリを作る。** <https://api.slack.com/apps> で「Create New App」→「From an app manifest」を選び、ワークスペースを選んで `slack-manifest.yml` の中身を貼り付けます。
2. **App-Level Token を作る。** アプリの「Basic Information」→「App-Level Tokens」で、スコープ `connections:write` を付けて作ります。`xapp-` で始まる値が出ます。
3. **ワークスペースに入れる。** 「Install App」でインストールし、「Bot User OAuth Token」（`xoxb-` で始まる）を控えます。
4. **`.env` を作る。** `.env.example` を `.env` にコピーし、2 つのトークンと自分のメンバー ID を書きます。
5. **ライブラリを入れる。**

   ```powershell
   bundle config set --local path vendor/bundle
   bundle install
   ```

6. **設定を確かめる。** `ruby bin/shiori check` で、トークンが通るか確かめます。
7. **試しに動かす。** `ruby bin/shiori` で起動し、Slack で bot に `?` と送って返事が来るか確かめます。止めるときは Ctrl+C です。
8. **起動時に自動で動くようにする。** 管理者として開いた PowerShell で次を実行します。

   ```powershell
   powershell -ExecutionPolicy Bypass -File scripts\install-task.ps1
   ```

   タスク スケジューラに `shiori` が登録されます。PC の起動時に、ログオンしていなくても動き出します。
   落ちても 1 分後に起動し直します。

## 運用

| やりたいこと | 方法 |
| --- | --- |
| ログを見る | `Get-Content data\shiori.log -Wait -Tail 50`（1 MB ごとに 5 世代まで残る） |
| 止める・動かす | `Stop-ScheduledTask shiori` / `Start-ScheduledTask shiori` |
| 自動起動をやめる | 管理者の PowerShell で `scripts\install-task.ps1 -Uninstall` |
| バックアップから戻す | タスクを止め、`data\backups\shiori-<日付>.db` を `data\shiori.db` に上書きして動かす |

バックアップは毎日 21 時の処理のあとに 1 つ作り、30 日分を残します。
`data\` は OneDrive の同期対象外なので、ほかの場所にも残したいときは別に写してください。

## 開発

```powershell
bundle exec rake test
```

| ファイル | 役割 |
| --- | --- |
| `lib/shiori/parser.rb` | Slack のメッセージをコマンドに変える |
| `lib/shiori/commands.rb` | コマンドを実行して返信を作る |
| `lib/shiori/store.rb` | SQLite の読み書き。履歴と取り消し |
| `lib/shiori/ranges.rb` | 読んだ範囲の合成、ページ数、未読の範囲、進捗バーのマス |
| `lib/shiori/stats.rb` | 進捗率、ペース、読了見込み、日ごとの読書量、日付の計算（日本時間） |
| `lib/shiori/render.rb` | Slack に出すメッセージ（Block Kit） |
| `lib/shiori/jobs.rb` | 週報と催促の中身 |
| `lib/shiori/schedule.rb` | 定期通知の時刻と、送り漏れの判定 |
| `lib/shiori/app.rb` | Slack から届いたものの振り分け |
| `lib/shiori/socket_mode.rb` | Slack との常時接続 |
| `lib/shiori/runner.rb` | 常駐プロセスの組み立て |
| `db/migrations/` | テーブル定義。起動時に未適用のものを流す |

テーブルを変えるときは、`db/migrations/` に番号の続く `.sql` を足します。既存のファイルは書き換えません。

## 設計の判断

- **記録の正本は GitHub Issues ではなく SQLite にした。** Issues では本文の書式を読み書きするのが壊れやすく、1 回の記録ごとに Actions を動かすので反映も遅れます。Slack から受け取るには常駐するプロセスが要るので、データもその隣に置きました。
- **サーバーではなくこの PC で動かす。** 外部サービスのアカウントを増やさずに済みます。止まっている間の弱点は、起動時の取りこぼし処理で補っています。
- **依存は 3 つの gem だけ。** `sqlite3`、WebSocket のフレームを組み立てる `websocket`、標準から外れる予定の `logger` です。HTTP と JSON は標準ライブラリで足ります。
